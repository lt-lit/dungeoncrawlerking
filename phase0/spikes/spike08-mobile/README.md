# Spike 8 — mobile engine benchmark page

Static page that runs the same benchmark suite as `spikes/spike08-perf.mjs`
(identical arenas via `bench-data.js`, regenerated by that script) against the
vendored Fairy-Stockfish WASM build, on the actual device that matters: a phone.

## Why this page exists

The engine build is a pthread build (references `SharedArrayBuffer`), so the
browser page must be **cross-origin isolated**. `coi-serviceworker.min.js`
handles that on static hosting (GitHub Pages) by installing a service worker
that injects COOP/COEP headers — the page self-reloads once on first visit.
Service workers require a secure context: **https or localhost only**.

## How to run on a phone

Option A — GitHub Pages (easiest, https):
1. Enable Pages for this repo (serve from the branch), visit
   `https://<user>.github.io/<repo>/phase0/spikes/spike08-mobile/` on the phone.

Option B — local network via port forwarding (Android):
1. On the dev machine: `cd phase0/spikes/spike08-mobile && npx http-server -p 8080`
2. Connect the phone via USB, open `chrome://inspect` on desktop Chrome,
   set up port forwarding 8080 → localhost:8080, then open
   `http://localhost:8080` **on the phone** (localhost = secure context).

Note: plain `http://<lan-ip>:8080` will NOT work — insecure origin, no service
worker, no SharedArrayBuffer.

## What to read off

- **Init time** (tap "Init engine"): threshold **< 3000 ms**.
- **Benchmark table** (tap "Run benchmark"): the *standard* arena row at
  movetime 500 should reach **depth ≥ 10**; nps column is the raw speed
  comparison against the Node numbers in `results/spike08-mobile-perf.md`.

## Vendored files

- `vendor/stockfish.{js,wasm}`, `vendor/stockfish.worker.js` — fairy-stockfish-nnue.wasm 1.1.11 (largeboard, pthread)
- `vendor/ffish.{js,wasm}` — ffish 0.7.9 (not exercised by the bench yet; vendored for follow-up legality benchmarks)
- `coi-serviceworker.min.js` — v0.1.7
